6. Key Functions
Atomic claim
sql

create or replace function claim_listing(p_listing uuid, p_ngo uuid, p_voluntee
returns uuid language plpgsql security definer as $$
declare v_pickup uuid;
begin
update listings set status = 'claimed'
where id = p_listing and status = 'posted' and pickup_by > now();
if not found then
raise exception 'ALREADY_CLAIMED_OR_EXPIRED';
end if;
insert into pickups (listing_id, ngo_id, volunteer_id)
values (p_listing, p_ngo, p_volunteer) returning id into v_pickup;
return v_pickup;
end $$;

Nearby listings for an NGO
sql

select l.*, h.name, st_distance(h.location, n.location)/1000 as km
from listings l
join hotels h on h.id = l.hotel_id
join ngos n
on n.id = $1
where l.status = 'posted' and l.pickup_by > now()
and st_dwithin(h.location, n.location, n.service_radius_km * 1000)
order by l.pickup_by;

Weekly score job (outline)
1. For each approved hotel with public_listing or not (all get a private score), take
pickups with status='completed' and voided=false in the last 60 days.
2. Compute each signal (definitions in the PRD, Section 8).
3. Apply smoothing, composite weights from settings , per-NGO cap on tag weight.

4. Set eligible = completed_pickups >= min_pickups ; rank within venue_type
category; assign tier.
5. Insert into score_snapshots . Voiding or correcting a pickup re-runs this for that
hotel.
Auto-flag triggers (on report submit)
portions_received differs from portions_listed by more than a configured

percentage.
photo_path missing, or collected_in_geofence = false .

Report completed more than 4 hours after collection.
NGO's recent reports are statistical outliers (low trust score).
